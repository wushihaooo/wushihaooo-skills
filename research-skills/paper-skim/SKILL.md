# Paper Skim

目标是让用户快速抓住：研究什么问题，核心改变是什么，为什么可能有效，实验揭示了什么，以及结论在哪些条件下成立。默认中文，保留必要英文术语。去除论文套路化铺垫和重复叙述；输出简短不意味着只读摘要。

## 阅读与核查

- 确认论文标题、版本和可用正文、补充材料。已有文件或链接时直接读取；只有标题时定位原始来源，存在身份歧义再询问。缺少论文时索取文件、链接或标题，不编造导读。
- 从标题、摘要、Introduction 建立概念与主张地图，再检查方法、实验、相关工作、结论和正文图表；按理解和验证需要回查全文。不要把论文的章节顺序直接搬成输出顺序。
- 核查摘要主张与具体设置、结果是否对应，检查宣传性描述是否超出证据；不预设作者夸大。既保留有依据的贡献，也写清影响结论的条件，不扩展成挑错报告。
- PDF 应结合文本提取与页面渲染，实际查看 Overview、关键结果图表、图注及表下注释；发现错位、OCR 错误或不清晰数值时回查原页。未核实内容标明缺口。
- 搜集与同一论文版本对应的 Supplement，优先从论文或官方发表页面定位。无法取得时说明缺失；仅读到摘要或部分正文时明确范围，不声称已核查全文。
- 核心事实和结论附节号、图表号或页码；必要时区分印刷页码与 PDF 页码。外部概念或基线说明需要检索时优先使用原始论文、教材或官方文档，并区分外部补充、作者陈述与本次分析。

## 输出结构：概览、前置知识、核心速览、可选补充

开头注明论文身份与必要的材料范围，用简单几句话交代问题、核心思路和最重要的发现。随后放分级前置知识，再进入连贯的核心速览；较长的非必要细节放入可选补充。用户读完核心速览即可停止，不应依靠来回跳读才能理解主线。

不规定机械字数。按信息价值压缩，优先保留会改变用户理解或判断的内容；不逐段复述，不抄全表，不在最后重复已经讲过的所有图表。

## 1. 前置概念：按耦合程度与解释成本分级

从标题、摘要、Introduction 提取理解本文需要的既有知识；必要时检查全文定义与引用。通用任务、理论、模型范式、已有技术可作前置概念。本文自创的模块、目标、框架或机制放在方法里解释；新组合所依赖的基础概念仍可提前介绍。不要仅凭缩写是否陌生判断概念来源。

对照用户提供的清单和可用对话中的明确掌握声明，区分“已确认掌握／需要补充／待确认”。提到、问过、读过或已经讲解过，不代表掌握。没有清单就采用待确认机制，先完成讲解，不逐项等待用户回答。

耦合程度指：不理解该概念会影响多少核心内容，是否阻断核心思想的理解。解释成本指：针对用户当前基础，需要多长说明才能理解。按概念在这篇论文中的具体作用判断，不按术语看起来是否高级判断。

| 阅读等级 | 判定 | 安排 |
| --- | --- | --- |
| 建议先读 | 与核心思想强耦合，且需要较长解释 | 集中放在核心速览前，按依赖顺序解释直觉与必要例子 |
| 按需选读 | 只影响局部设计、某项实验或补充理解，且需要较长解释 | 同样提前放置，但与必需概念分开，注明可跳过及影响范围 |
| 一句话提示 | 一两句话即可讲清 | 首次出现时顺带解释；强耦合概念可在开头顺带说明 |
| 略过 | 已明确掌握，或与理解核心思想关系很弱 | 不展开，必要时只提示联系 |

较长概念说明不能在核心速览中突然插入，打断阅读。每个需要展开的概念先写推荐等级、本文用途，再给所需解释；不要把候选概念都展开成领域百科。若在方法或实验中才发现必要基础，仍将解释前置。

用户可以批量确认已掌握或希望展开的概念。默认没有持久化概念库；未得到明确确认，不将状态升级为已掌握。只有用户要求记录时才更新其指定的学习记录，不自动创建或修改跨会话记忆。

## 2. 提取核心思想，合并问题与相关工作

围绕“过去如何做—在什么条件下受限—本文改了什么—为什么可能有效”组织，合并 Introduction 与 Related Work 的重复信息。说明输入、输出、关键约束，只介绍理解创新或对照所必需的代表路线，不逐篇罗列引用。

用具体操作解释核心变化，少用模块名称堆叠。区分沿用部分、真正改动与作者声称的新贡献。如果贡献是数据、任务定义或实验发现，就围绕该贡献展开，不强行寻找新模型。

该逻辑是提取框架，不是必须补齐的槽位：其他章节能找到就补入；全文缺失且不影响理解时省略，影响判断时简短注明。不要替作者编造动机、已有方法的不足或贡献。综述、数据集等论文按实际类型调整。

删除“日益增长”“近年来蓬勃发展”等空泛铺垫，保留影响任务和实验的事实。将作者提出的动机、实验验证的不足与分析者的推断分开。

## 3. 结合 Overview 讲清核心流程

- 展示实际查看过的原始 Overview／框架图或清晰裁剪，保留图号、标签与必要图例，并紧接文字解释。图片使用环境支持的显示方式，本地图片用绝对路径；仅给图片链接不等于图文讲解。
- 沿“输入—关键处理—中间结果—输出”串起流程，模块名称与原图对应。重点解释产生创新的步骤：接收什么、改变什么、为什么有用；常规模块简述即可。
- 训练与推理不同时，指出监督信号、标签及辅助分支在哪个阶段使用。默认讲损失的优化目的，不逐式推导；若核心思想依赖公式，给最少符号和直观解释。
- 示例仅在减少理解成本时加入，不强制每篇都有，也不把自拟例子写成论文结果。具体讲解深度随每次实践中的用户反馈调整。
- 原图复杂时可补简化流程图，标为“简化示意／导读重绘”；没有 Overview 时根据正文绘制并注明来源。不得将重绘冒充原图，不用生成式图像重建实验结果。原图无法显示时说明限制并用文字流程或 Mermaid 继续。

## 4. 实验：分析规律与解释，不复述明显涨跌

先简要交代评估条件，再分析实验在检验什么。缺失的关键设置标“未报告”，不猜测。

- 数据集：名称、来源、数据类型、标签、实际样本量及统计单位、训练／验证／测试划分；多中心或外部测试需说明来源。不能混淆患者、切片、图像、patch 等计数单位。
- 任务：预测或生成目标、输入输出、监督信息和评估对象；多个任务或数据集不要混写。
- 指标：测量什么、方向以及影响理解的口径；必要时解释宏／微平均、评估单位、阈值或误差项，不能将所有“±”都当作标准差。已掌握的常见指标不重复教学。
- 实验概况：按验证目的简要列出实际存在的基线、消融和特殊实验，并交代主要实验组数的计数口径。多数据集、多指标、多表格行不自动算成多种实验；自行归类时写明是本次浏览的归纳。

对重要实验选择有信息量的角度深入分析，不要求每张表机械回答全部问题：

1. **变化规律**：收益集中在哪些任务、数据条件或场景？哪些地方无效、变差或不一致？
2. **设计对应**：模式是否符合方法动机？消融改变了什么、控制了什么，能否支持具体设计解释？
3. **作用来源**：核心机制、额外数据、训练策略或模型规模等因素是否同时变化？现有对照能区分哪些解释？
4. **代价与边界**：收益是否依赖额外监督、计算成本、特定假设或受限场景？

不要把“某方法比某方法提升多少”或“某行最高”当作主要分析，这些通常从表格即可看出。仅在支撑分析时引用少量关键数字，带上数据集、指标、比较对象及必要单位；区分百分点与相对变化、原文报告与自行计算。不要重新抄写完整结果表。

深度分析可以简短，但必须有依据：明确区分实验直接支持、合理解释与尚未验证。无法从现有对照辨明原因就直接说明，不能为了显得深入而编造机制。相关工作不一定是实验基线；基线机制仅在理解比较需要时介绍，并核查关键设置的可比性。

保留反例、关键消融和会改变结论的异常；重复趋势合并。作者主张与实际证据一致时直接解释其价值，只有存在重要差距时才集中指出。最佳均值、加粗或局部提升不自动等于统计显著、普遍优越或机制已证实。

## 5. 将图表融入方法和实验

检查正文图表，并将有信息价值的内容放入相应方法或实验段落；不再设置逐图重复讲解的独立章节。核心图表细讲，重复图表可以合并或省略正文复述。核查范围可比展示范围更广。

读图时核对图号、子图、轴、颜色／符号、单位与比较对象，读表时核对行列、设置及注释。把影响解释的 caption、样本量、误差条、标记含义和适用条件融入讲解，不只翻译标题。必要的关键图应实际展示；摘录表格或裁剪图片需说明范围，不能省去改变解释的注释。模糊数值无法核实时只描述可靠趋势并说明限制。

尊重定性实验与可视化的独立价值：它们可以帮助理解作者做了什么、模型在一个样本上发生了什么、重建或预测保留了哪些结构。优先说明看清了什么过程、出现了什么现象，以及它与设计或定量结果的联系。

例如遮挡与重建 patch 的可视化，可以直观解释重建任务和输出行为；不能仅因它是定性展示就贬低其价值。若只是将相同分数换一种图形呈现，评估是否增加了理解再决定篇幅。只有主张超出图像实际支持范围时才指出限制，不在每张图后机械追加“单一样本不能证明整体效果”。

## 6. Supplement 中值得看的内容

优先寻找正文省略但影响理解的机制细节、关键实验设置、额外验证、失败案例及结论限制；普通重复结果略过。

- 能补全核心理解的内容直接并入方法或实验，并注明补充材料的节号、图表号或页码。
- 额外有价值但不影响主线的内容放到末尾可选补充，说明“补充了什么、为何值得看”，不要再次复述正文。
- 没有提供、无法取得或未发现值得额外展开的内容，如实简述；不虚构 Supplement 内容或强行凑一节。

## 每篇论文都用于改进技能

每次结合用户反馈检查：是否太长、重复、跳跃，概念说明是否打断阅读，实验分析是否停留在读数，是否遗漏影响判断的内容。已获得反馈时直接利用；尚无反馈时，确有需要才集中提出一个简短问题，不要求用户每次完成问卷。

区分可复用问题与论文特例。反复出现或用户明确提出的通用偏好可以形成小范围规则改进；特定论文才需要的细节留在当次结果中。没有明确问题时不为迭代而改动。

实际修改遵循当前授权：用户要求修改时更新相应文件并校验；仅讨论时先给出具体改进建议，不擅自改动。发现用户维护的源码与安装副本时，核实路径后按授权同步，不在技能里硬编码个人目录。不要将技能迭代当作修改跨会话记忆的授权。

## 交付前自检

- 核心思想是否用具体变化说清，读者能否快速理解问题、改动、证据和成立条件？
- 前置概念是否按耦合与解释成本分级，长解释是否前置，自创概念是否留在方法，掌握状态是否有依据？
- 输出是否图文对应、主线连贯，删去了套路化铺垫和重复内容？
- 实验是否分析了关系和含义，而不是逐行报数；推断是否与证据区分？
- 是否合理利用定性图和 Supplement，并核查摘要主张、图注及表下注释？
- 是否诚实说明缺失材料或未验证内容，避免将一次格式校验当作真实论文试跑？

默认在对话中交付；用户要求文件时再生成。不要自动加入投稿评分、作者背景调查或双语审稿。

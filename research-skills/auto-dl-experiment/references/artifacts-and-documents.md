# 产物、目录与文档规范

## 共同写作原则

所有文档服务于人类快速理解和介入实验：只写与本文目的直接相关的事实、判断和必要细节。用短段落、表格或图表达，避免重复背景、审计流水账、无关目录和操作历史。原始证据独立保存，正文仅在支撑关键判断或导航时链接；不强制附更新日期或统计明细。技术协议保留必要的冻结信息，审批记录保留实际授权信息；“简洁”不等于遗漏影响决策的事实。

## 目录说明：EXPERIMENT_DIRECTORY_STRUCTURE.md

直接按[用户目录结构模板](../assets/EXPERIMENT_DIRECTORY_STRUCTURE.md)适配。标题为“实验目录结构”，以一张带行内用途注释的目录树为主体，通常一页左右即可。展示数据、文档、代码、配置和产物的位置，并展开一个代表性实验目录；省略无助于定位的层级和文件。

树后用短表解释有意义的文件名字段（如任务、方法、版本、折、种子、epoch），只解释项目实际使用的字段；写清版本之间、版本与单次运行之间如何组织，并给出结果索引入口。区分现有布局与未来约定，不将规划目录写成已存在。不加入审批回顾、核验数量、存储快照、工具实现或长篇保存规则。

## 文档1：01_DATASET.md

**目的：让读者快速看懂数据来自哪里、有多少病例与切片、类别如何分布、各模态包含什么。** 用户修改过的结构与详略优先作为模板。多个数据集逐个使用同一结构，先说明它们之间的关系；不要把 Dataset 写成目录导航、实验日志或审计报告。

推荐正文结构（按实际任务调整）：

1. **数据集简介**：一小段交代来源、任务和该版本的筛选条件；给出原始数量、各类实际排除数量、最终可用数量。公开性沿用用户说明，未知仅简短标注。需要路径时只放关键图像/特征和标签位置，不展开文件夹树。
2. **图像模态／病例构成**：用表格列训练、验证、二者合计、测试、总计及类别占比。分母写清楚；没有固定训练/验证划分时按真实开发集或交叉验证结构呈现，不为了套表新划分数据。
3. **切片构成**：同样列各分区、总量及各类病例所属切片数与占比。切片继承病例标签不等于独立切片结局标注。合计与分项不可重复相加。
4. **规模统计**：默认仅列每切片 patch 数、每病例切片数、每病例 patch 数的最小值、中位数、最大值；必要时补总 patch 数。每张表明确统计队列范围，不能把开发集统计称为全数据集。图像特征用一句说明提取器、维度/形状及已知的倍率等关键属性。
5. **文本及其他模态**：简要说明内容与匹配单位，再以“字段名称／简介／例子”表呈现，解释单位、编码和结局字段。使用标明为示意的虚构或脱敏例子，不直接复制病例原文。共有字段可复用字段说明，不机械重复。报告缺失与某个字段缺失、清洗后无有效文本必须区分。
6. **必要说明**：只保留影响数据理解的少量限制；有证据就填，没有则简短写“待补充”，随后补全。正文不附统计更新时间、统计明细链接或审计入口，不列核验动作、哈希、历史模型版本或未开展的工作。

统计要求：

- 对 `xxx` 等可计算占位项先统计并填写；核实排除原因及重叠关系，不把“未匹配清单”直接改写为“缺失图像”或“缺失文本”。计数需可对账，比例使用同一明确分母。
- 区分病例、患者、WSI与文件，保留真实标签语义。生存任务报告事件/删失而非虚构类别；多标签计数可以重叠。预提取特征中的有效 patch 不等于整张 WSI 的全部像素。
- 全队列统计使用完整清单或文件形状；抽查不能冒充全量。详细分位数、极值切片 ID、空切片数、逐病例/逐片统计、特征与预处理溯源、文本时点/长度/截断/缺失审计另存 `artifacts/data_audit/`，不附加到正文或文末。
- 不由特征维度猜提取器或倍率，不将未记录的信息写成已确认事实。未知项保持简短，逐步完善；不为表面完整扩大文档。

若只有原始 WSI、没有预提取特征，将实际特征统计标为“尚未生成”，在协议中提出待确认的提取方案；不虚构维度和有效 patch 数。步骤1先确认可得事实及计划，批准的特征准备纳入步骤3的公共数据管线与资源预算，生成后补齐文档和输入审计，再冻结基线训练协议。新增实质数据排除或输入改变须回到相应文档确认。

## 文档2：02_EXPERIMENT_DETAILS.md

**目的：让读者快速理解数据怎么划分、模型怎么公平训练、如何选模型和汇总评价。** 优先保留用户修改后的章节与详略，以短段落和必要表格补齐歧义，不扩成历史实验目录或核验报告。

推荐结构：

1. **数据集划分**：说明划分单位、比例及分母、固定测试集和 K 折轮换方式、同病例切片不跨分区。区分“开发集内部比例”和“占整体比例”，不重复 Dataset 中的大量计数表；分层因素按实际协议写。
2. **随机种子设置**：正文直接保留用户确定的种子及是否做多种子实验，不能强制隐藏到审计附件。区分折数与种子数，不擅自增加多种子平均。真实分区清单与复现元数据另存。
3. **训练公共设置**：单次配置比较保持公共设置一致；超参数搜索保持预算和选择规则公平。学习率、权重衰减、Dropout、优化器、有效 batch、最大 epoch 等有已定值就简洁列出，未定值留待批次协议填写，不从历史版本猜填。简要保留适用的输入与聚合约束，方法特有设置单独说明。
4. **实验指标**：采用“指标／简介”短表，覆盖用户指定指标及理解结果所需的少量辅助指标，注明评价单位、阳性类、方向、必要公式及阈值口径。不要漏掉选轮用的 AUC，也不为了齐全堆入无关指标。生存任务改用对应的 C-index、时点 AUC、Brier/IBS 等，另明确删失处理与评价时点，不套用分类定义。
5. **选轮与结果汇总**：写清每折验证选轮指标、方向、并列和早停规则，再说明固定测试集如何评价。逐折指标均值、合并 OOF 指标和模型集成指标不是同一结果；折间标准差不能当作独立测试集或多随机种子的不确定性。汇总方式与阈值在测试前确定。
6. **损失与不平衡处理**：保留用户指定方案，解释关键权重来源及采样单位，验证和测试保持原始病例分布。损失加权和重采样不是同义词，组合使用须说明叠加作用。若与项目现有约束冲突，先指出具体冲突并核对授权；用户明确选择偏离后单独标记探索性方案，不混入原协议公平比较。

本文中的具体比例、种子、损失和采样器均取自当前用户与任务，不将某次示例中的 80/20、五折、42 或 Focal Loss + Weight_Sampler 固化为其他项目默认值。当前约定与历史实际设置不一致时，用一句话区分适用范围；历史细节保留于原协议或已有附件，不追溯改写已完成实验，也不因文档修订启动训练。

## 文档3：03_EXPERIMENT_PROTOCOL.md

**目的：让读者快速知道做什么任务、希望达到什么目标、与哪些方法比较。** 优先沿用用户模板，通常只需以下三部分：

1. **任务类型**：一小段说明预测单位、输入模态和输出标签；明确图像基线与多模态方法的输入差别。
2. **任务目标**：明确主要评价指标与比较目标，必要时一句说明共同评价规则。目标是待检验的研究方向，不写成已经取得的结果，也不保证必然超过基线。
3. **基线方法**：用“方法名称／方法简介／是否多模态”表逐一说明。根据论文或实际实现补齐占位项，每种方法以一句话解释核心机制；区分原版与实际适配版本，不凭缩写猜方法或把所有 MIL 都写成多模态。仅保留影响比较理解的简短补充。

不重复 Dataset 的统计表和实验细节中的超参数、选轮与指标公式，不加入历史证据目录、流程状态、修订日期、统计明细或审计链接。必要的方法出处可直接附在方法名上。三份背景文档共同遵循这一简洁原则；支撑记录独立保存，不要求正文提供入口。

## 基线结果：BASELINE_REPORT.md

直接沿用[用户基线报告模板](../assets/BASELINE_REPORT.md)：公共超参数表、方法特有超参数表、验证集结果表、测试集结果表。公共表简要写明种子、优化器、学习率、权重衰减、Dropout、有效 batch、训练上限、早停、损失、采样、梯度裁剪与计算精度；方法表只列结构及辅助损失的关键差异。使用该批次真实配置，区分待执行与已执行状态；不把模板数值固化为默认值。

验证与测试分别报告同一组选中 checkpoint 的全部指标，不能每项指标各取最佳 epoch。多折时验证表汇总各折自己的验证分区；测试表说明是同一固定测试集还是外层测试折。简要说明均值与标准差的计算方式、分类阈值、正类及混淆矩阵顺序和计数汇总方式；不混淆折均值、合并 OOF 与模型集成。验证表注明选轮偏差，折间标准差不作置信区间；未完成的单折诊断不混入正式多折结果。

基线没有方法编号，不在方法名后标历史实验版本；未知或尚未按当前协议完成的结果留空。均值、标准差、阈值和混淆矩阵口径需要解释时仅加简短说明。机器证据和逐折明细放实验产物中，不将报告扩成历史目录、审核流水账或步骤记录。用户授权补跑后才按当前协议补足；单纯修改报告不构成新增实验授权。

## 每轮 PROTOCOL.md

每轮实验的 `PROTOCOL.md` 承载具体研究与执行约定，不能因为总体说明简化而省略正式实验所需的判据和复现信息。正式运行前固定本批次参数并保存不可变副本，至少包含：

1. 任务类型、预测单位、预测时点、输入/输出张量及语义、目标人群与标签定义。
2. 假设、支持与反例（原始证据链接）、本轮改变、固定基线与匹配对照。
3. 主要指标及方向、次要指标/重要不退化项、验证选轮、阈值、最终测试访问规则。
4. 数据使用、划分与排除规则、训练预算、搜索范围、随机性和可复现审计位置。
5. 预先量化的效果门槛及其依据、区间/检验方法、机制诊断、诊断充分性、成功/失败/证据不足判据。没有依据时与用户确认合理探索目标，不机械继承旧实验的 +0.02 等门槛。
6. 预设消融/干预及替代解释、技术失败处理、算力估计和审批范围。
7. 协议状态、版本、冻结时间和哈希；变更另存版本与原因，不能覆盖已出结果的判据。

## 状态与审批记录

`WORKFLOW_STATE.json` 至少保存 `project_root`、`dataset_roots`、`step`、`method_id`、`protocol_version`、`protocol_hash`、`status`、`artifact_paths`、`pending_decision`、`last_approval_ref`、`batch_id`、`approved_batch_scope`、`consecutive_technical_failures`、`updated_at`。可用状态：`in_progress`、`awaiting_input`、`awaiting_step_approval`、`awaiting_compute_approval`、`awaiting_paradigm_approval`、`awaiting_failure_decision`、`complete`。

步骤8交付时仍是 `awaiting_step_approval`；用户确认收尾后才是 `complete`。状态文件是恢复索引，不是权限来源。`APPROVALS.md` 追加实际用户回复、日期、对应步骤/批次/版本与批准范围；审批工具返回“已提交问题”不等于已批准。

## 每轮经验条目

记录方法编号、假设、相对前轮改变、主要/次要指标、匹配基线、效应区间、机制干预、支持与反证、尚未解决的替代解释、人类判断、可继承经验、避免重犯项和原始证据路径。基线阶段的经验也在索引记录。运行中只写待验证，不填未来结果。

仓库已有中心台账时同步追加简洁结论和链接。没有台账则在批准的目录建立；首轮冻结前可快照仅含背景与待验证状态的初始台账，不虚构历史。保存快照时包括经验索引和本轮相关记录，避免单纯复制索引后其链接内容继续变化。
